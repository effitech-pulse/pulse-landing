## Что это
Система предиктивной диагностики УЭЦН (электроцентробежных насосов) на
нефтяных скважинах Татнефти. Грант, упор на промышленную систему.
Цель: прогнозировать отказ за 7–14 суток до события.

## Данные
- ~1000 скважин (500 с отказами / 500 нормальных), масштабирование до ~1700.
- Телеметрия: до 50 параметров, сырая дискретность 3–60 с, пишется по
  изменению (deadband), приводится к регулярной сетке.
- Источник — архив IRZ (utils/parsers/irz_archive_downloader.py).
- Схема параметров: utils/parsers/params/*.json (alias, displayname, eu,
  server_parameter с coef_k/coef_b, is_set, server_data_type_id).
- Дебит — раз в сутки (факт и ожидание).
- Метаданные скважин: месторождение, цех, тип насоса, глубина.
- 13 типов отказов (таблица технологов, см. ниже) + «норма» + детекция
  «неизвестной аномалии». В среднем ~33 примера на класс — сильный дисбаланс.

## Архитектура (целевая) — маршрутизирующий каскад, НЕ один плоский классификатор
- Стадия 0: гигиена данных — детерминированные правила (потеря связи,
  frozen-data), очистка маркеров-заглушек.
- Стадия 1: детектор аномалии (LSTM-AE / forecasting-error) + дрейф-детектор.
- Стадия 2: маршрутизатор по бакету динамики.
- Стадия 3: тонкая классификация / survival внутри бакета.
Бакеты по динамике:
- SLOW (дни-недели, ML-ядро, прогноз 7–14 сут): #1 парафин, #2 соль,
  #5 ВНЭ, #10 износ РК.
- MECHANICAL (тренд вибрации/недогрузка): #6 слом вала, #8/#9 засорения.
- FAST (секунды-минуты, real-time правила/MCSA): #7 смена режима,
  #11 изоляция, #12 ЧРЭП/сеть.
- SYSTEM (правило, НЕ ML): #13 потеря связи.

## 13 типов отказов (сигнатуры технологов = labeling-функции)
1. Парафин в НКТ: рост Рлин при const частоте, падение дебита, рост
   мощности, ЗСП, рост Tобм ПЭД и Tприёма, режим огранич. по T на пониж. f.
2. Соль в насосе: падение напора при фикс. f, рост тока, ЗСП, ток в полосе
   (ХХ, номинал) + флуктуации, режим огранич. по T.
3. Утечка НКТ верх. интервал: падение дебита, рост Рпр, резкое падение
   дебита, режим огранич. по T.
4. Утечка НКТ ниж. интервал: рост Рзатр, резкое падение дебита, рост Рпр,
   ток ≤ ХХ.
5. ВНЭ (эмульсии): падение нагрузки ПЭД по мощности и току, рост Рбуф/Рпр,
   ЗСП, падение cos φ, режим огранич. по T.
6. Слом вала: рост тренда вибрации, биение ротора, Рпр падает в пр. 2 атм,
   ток ≤5% от ХХ, cos φ < 0.55.
7. Смена условий (Рпл/Рзаб): скачок обводнённости/ГФ, резкое изм. Рзаб,
   ЗСП, резкая флуктуация тока, пониж. f.
8. Засорение насоса: ток в полосе (ХХ, номинал) + флуктуации, рост Рпр,
   режим огранич. по T.
9. Засорение приёма: сигнатура как у #8 (телеметрически почти неотличимо).
10. Износ РК: падение дебита, рост удельн. энергопотребл., ток >ХХ на >5%,
    cos φ < 0.55.
11. Деградация изоляции: падение/флуктуации R_izol, дисбаланс токов.
12. ЧРЭП/сеть/перегрев СУ: нелинейная нагрузка, асимметрия фаз, уставки
    ЧРЭП, провалы напряжения.
13. Потеря связи: «застывшие»/frozen данные, сигнал отсутствия связи.
Трио #2/#8/#9 телеметрически почти неразличимо — на старте объединять в
суперкласс «механическое засорение/отложения».

## Реальные alias параметров (из params/*.json)
F_out (частота), Motor_winding_temperature, Vibration_X/Y/Z/XY/XYZ,
Pump_intake_pressure_kgs, Annulus_pressure (set_Annular_pressure — уставка!),
CosF, Ped_load, Ia/Ib/Ic (токи фаз), R_izol (изоляция), I_disbalance,
U_disbalance, DHS_state (состояние ТМС / связь), Bottomhole pressure (расч.),
Flowrate for current/previously day, stat_Number_stop_* (счётчики ЗСП).

## Ловушки данных (ОБЯЗАТЕЛЬНО учитывать везде)
- Маркеры-заглушки сбоя датчика, НЕ ноль: 9999 (R_izol, реактивная энергия),
  999.9 (реактивная энергия кВАр*ч). Заменять на NaN ДО любой агрегации.
- Простой установки: F_out=0, токи=0, дебит=0 — это ВАЛИДНЫЙ ноль, не пропуск.
  Не путать с маркерами. Признак is_running = F_out > порога.
- Уставки (server_parameter.is_set=true, напр. set_Annular_pressure) — не
  датчик; нельзя мешать с измерениями (утечка).

## Инварианты (нарушать НЕЛЬЗЯ — это про корректность ML)
- Temporal split: train строго до даты X, test после. Никогда не случайно.
- Group split по месторождению: скважины одного месторождения не делить
  между train/test.
- Purge/embargo: убирать окна в пределах горизонта прогноза от границы
  train/test.
- Leakage-чек: признак соседей «отказов за 30 дней» строго причинный по
  времени; per-oilfield нормализация фитится только на train-периоде;
  novelty-AE учится только на нормальных окнах вне пред-отказного интервала.
- Метрика: recall по каждому из 13 классов (пропуск дороже ложной тревоги),
  F1-macro, confusion matrix. Порог алерта — cost-sensitive.

## Фактическое состояние (важно)
- **Формат alias.** В params/*.json alias имеет device-префикс:
  `"4x0101 R_izol"`, `"4x010D F_out"`. Каноническое имя (как в этом файле:
  `R_izol`, `F_out`, `Vibration_X`) = alias без префикса `4xXXXX `/`3xXXXX `.
  Пакет `esp/` работает с каноническими именами; маппинг — из params.json.
- **Колонки CSV ≠ alias.** Парсер пишет колонки русскими displayname
  (`"Давление на приеме ЭЦН, ат"`), не alias. Поэтому `esp/naming.py` сначала
  канонизирует колонки, потом работают правила.
- **Где параметры:** `base.json` (узкий набор), `large.json` (полный ~50
  каналов: вибрации, токи Ia/Ib/Ic, R_izol, I/U_disbalance, DHS_state),
  `ml.json` (набор под ML). Реактивная энергия:
  `energy_Input_energy_reactive_total_kW/MW` (маркеры 9999/999.9).
- **Канонический набор скачивания = `large.json`** (решение пользователя).
  Поле `unitek.params_path` в обоих batch-конфигах указывает на
  `utils/parsers/params/large.json`; `aliases: null` = качать все его tags[].alias.
- **Стек парсера** перенесён из референса в `utils/parsers/` (irz_archive_downloader,
  run_batch, unitek_period_downloader, armits/, yadisk_*, _http_base). Внешние
  зависимости: `requests`, `python-dotenv`.
- **Секреты/живые выгрузки:** креды лежат в `utils/parsers/.env` (gitignore).
  Для живых запросов парсер грузит `load_dotenv(<grant-root>/.env)` — т.е. нужен
  `grant/.env` с `UNITEK_*` (телеметрия) и `ARMITS_*` (дебит). Для офлайн-тестов
  Фазы 1 (регрессия ресемпла на синтетике) `.env` и сеть НЕ нужны.
- **Образец данных:** `tests/fixtures/sample_day.csv` (1440 строк, base-каналы,
  без R_izol/вибраций — правила изоляции/ЧРЭП на нём корректно SKIP).

## Памятка по сквозным правилам
- Никаких утечек: temporal + group(месторождение) + purge/embargo всегда.
- Маркеры-заглушки (9999/999.9) → NaN до любой агрегации; валидный ноль не трогать.
- Обратная совместимость парсера — жёсткий инвариант (Фаза 1).
- SMOTE на сырых окнах запрещён (только focal loss + веса + аугментация).
- Усложнение модели принимается, только если бьёт предыдущий бейзлайн в той же CV.
- Каждый алерт объясним (какой параметр/стадия сработал) — для приёмки технологами.
- Трио #2/#8/#9 — суперкласс на старте.
- Каждая фаза: краткий план → одобрение → код + тесты → выполненный DoD.
